# 🔁 Mobilisation compensatoire -- Suramplification

> *"Le langage bascule de 'ça sert à X' vers 'c'est le travail'. La construction devient autotélique."*

---

## I. L'opération neutre — Mobilisation compensatoire

**Définition fonctionnelle :** Quand une faiblesse est identifiée dans un domaine important, le cerveau mobilise des ressources supplémentaires pour la combler. C'est une réponse adaptative — s'engager davantage face à un défi réel produit de la croissance. La dysfonction survient quand l'engagement devient disproportionné à l'objectif initial.

> [!abstract] ✅ Fondement — Cacioppo & Petty (1982) · [[Fondements théoriques/08 — Need for Cognition]]
> Pour un profil NFC élevé, la complexité d'un domaine est intrinsèquement récompensante — ce qui peut amplifier l'engagement bien au-delà du point de rendement optimal. [documenté]

> [!abstract] ✅ Fondement — Dweck (2006) · [[Fondements théoriques/09 — Mastery orientation · Entity theory]]
> Le mastery thinker s'engage plus face aux défis — mécanisme adaptatif. La Suramplification est ce même mécanisme poussé au-delà du rendement optimal, souvent co-activé par une menace entity sur la faiblesse identifiée. [inféré depuis Dweck 2006]

> [!abstract] ✅ Fondement — Caillois (1958) · [[Fondements théoriques/10 — Agon · Alea · Mimicry · Ilinx]]
> La disposition Agon traite la faiblesse comme un adversaire à battre — ce qui mobilise une énergie supplémentaire que NFC et Mastery amplifient. [documenté]

**Modulation par L0 :** sous budget satisfait, la mobilisation peut rester calibrée. Sous budget épuisé, le signal d'arrêt naturel est moins perçu — la mobilisation continue au-delà du point de rendement.

---

## II. Cartographie des pôles

#### A. Pôle défensif — Suramplification

> **Rappel architectural :** la Suramplification est activée par l'interaction entre la menace sur le L1 Compétence défensif ET les moteurs génératifs (NFC, Agon, Mastery). C'est l'un des rares L2 où les pôles défensif et générateur partagent le même déclencheur de surface — c'est l'excès qui crée la dysfonction.

**Expression 1 — Complexity creep (projet de construction)**
- **L1 actif :** Besoin de Compétence en mode défensif
  *Ce qui est menacé :* une faiblesse identifiée dans un domaine d'identité important — la construire à fond protège l'entité
- **Mécanisme L1→L2 :** faiblesse identifiée → menace Compétence → activation défensive → NFC rend la complexité intrinsèquement récompensante → Agon traite la faiblesse comme adversaire → Mastery voit l'adversité comme informationnelle → les trois ensemble produisent un engagement maximal et accéléré → complexity creep : le système construit dépasse progressivement l'objectif initial → la construction devient autotélique
- **Condition déclenchante :** faiblesse identifiée dans domaine d'identité + profil NFC élevé + L1 Compétence défensif
- **Lien entity thinking :** l'entity thinking sur la faiblesse ("je ne suis pas encore assez bon à X") charge l'engagement identitairement. Le mastery thinking sur le processus ("c'est fascinant") donne l'énergie. Les deux combinés → Suramplification. → [[Fondements théoriques/09 — Mastery orientation · Entity theory]]
- **Signal de dérive :** vocabulaire bascule de "ça sert à X" vers "c'est le travail"
- **Output 1 — Abandon :** charge trop lourde, objectif initial insuffisamment ancré
- **Output 2 — Charge chronique :** système actif mais coûteux sans proportionnellement servir la performance
- **L3 générée :** [[La Réactance]] (si freiné) · [[Honte]] (si le projet échoue)
- **Statut :** [observation personnelle — GTO Lens abandonné · Inner Mapping risque identifié]

**Expression 2 — Suramplification en session perdante**
- **L1 actif :** Besoin de Compétence défensif
  *Ce qui est menacé :* la session perdante expose une limite de l'entité compétente
- **Mécanisme L1→L2 :** session perdante → variance hostile joue le rôle d'adversaire Agon → engagement maximal et accéléré → volume augmenté · niveau parfois monté → sans calibration sur le budget L0
- **Condition déclenchante :** session à -3/5 buyins + NFC + Agon actif + L0 progressivement épuisé
- **Output typique :** "tilt d'orgueil" · sessions trop longues · dégradation du jeu par épuisement
- **L3 générée :** [[Frustration]] · [[La Réactance]]
- **Statut :** [documenté — asymétrie session length identifiée]

#### B. Pôle générateur — Mobilisation calibrée

**Expression 1 — Mobilisation avec recalibrage régulier**
- **Condition :** faiblesse identifiée + NFC + mastery thinking + question de recalibrage active
- **Mécanisme :** engagement fort sur le domaine + question pivot régulière : *"Est-ce que cette complexité sert encore l'objectif initial ?"* — posée pour orienter, pas pour freiner
- **Lien mastery thinking :** l'objectif reste l'usage, pas la construction. La complexité est un moyen, pas une fin. → [[Fondements théoriques/09 — Mastery orientation · Entity theory]]
- **Output typique :** progression réelle · système proportionnel à l'usage · budget préservé
- **L3 générée :** Satisfaction · Certitude
- **Statut :** [observation personnelle — Inner Mapping avec Claude + Alexis = distribution de charge]

## IV. Connexions dans l'écosystème — Bidirectionnel

| Niveau | Sens | Connexion |
|---|---|---|
| **Opération neutre → L0** | intrinsèque | Coût élevé — la mobilisation maximale consomme intensément le budget corporel |
| **L0 → L2** | descendant | Budget épuisé → signal d'arrêt moins perçu → Suramplification plus longue avant détection |
| **L2(défensif) → L0** | ascendant ⚠️ | Engagement maximal prolongé = épuisement progressif · charge chronique si le système reste actif |
| **L2(générateur) → L0** | ascendant ✅ | Mobilisation calibrée avec recalibrage : engagement productif sans épuisement · NFC récompensant → peut être énergisant |
| **L1 → L2** | descendant | Besoin de Compétence défensif (faiblesse menaçante) + NFC + Agon → Suramplification · Compétence générateur → Mobilisation calibrée |
| **L2(défensif) → L1** | ascendant ⚠️ | Répétition renforce "l'engagement maximal est la réponse aux faiblesses" → ancre le Perfectionnisme protecteur |
| **L2(générateur) → L1** | ascendant ✅ | Mobilisation calibrée avec recalibrage régulier consolide "l'effort doit servir l'usage" → renforce la Compétence générative |
| **L2 associés** | latéral | Scattering (Suramplification → épuisement → Scattering) · Suranticipation (session gagnante = Suramplification peut s'inverser) |
| **L3 produites** | descendant | Réactance · Honte · Frustration (défensif) · Satisfaction · Certitude (générateur) |
| **L4 comportements** | descendant | Étude compulsive · augmentation du volume en session perdante · projets abandonnés |

**Distinction des schémas proches :**
- vs **Scattering** : la Suramplification est un engagement *maximal* sur UN domaine. Le Scattering est une *fragmentation* sur plusieurs. La Suramplification peut provoquer le Scattering par épuisement.
- vs **Rumination** : la Rumination est passive et rejoint le passé. La Suramplification est active et orientée vers l'action future.

## V. Régulation — Stratégies Gross 
[[Fondements théoriques/06 — Contrôle perçu & régulation émotionnelle]]

| Stratégie | Moment d'intervention | Application concrète |
|---|---|---|
| 1 · Sélection | Avant la situation | Question de recalibrage régulière : *"Quelle est la prochaine action concrète que ce système devrait permettre de mieux faire ?"* |
| 2 · Modification | Pendant — amont | Distribuer la charge d'exécution (partenaire) · définir une limite de durée avant de commencer |
| 3 · Attentionnel | Pendant — amont | Maintenir l'objectif initial visible dans le fichier de travail |
| 4 · Reappraisal | Pendant — aval | — (la Suramplification est nourrie par l'énergie — le Reappraisal est peu efficace contre elle) |
| 5 · Modulation | Pendant / après | — |

**Stratégie prioritaire :** Sélection (1) — la question de recalibrage. Simple à poser, puissante pour détecter la dérive avant qu'elle devienne trop coûteuse.
**Signal d'alarme avancé :** charge mentale liée au système lui-même, pas à la tâche originale.
**Note L0 :** la question de recalibrage est moins accessible sous budget épuisé. La poser en amont avant de lancer un nouveau chantier.

## VI. Signaux de détection

> [!warning] Le pattern Suramplification est actif quand...
> - Le vocabulaire bascule de "ça sert à X" vers "c'est le travail" sans référence à l'usage
> - La charge mentale est liée au système lui-même, pas à la performance
> - La réponse à "quelle est la prochaine action que ce système permet de mieux faire ?" est floue
> - La session perdante génère une augmentation du volume plutôt qu'un retour au budget
>
> **Question de détection :** *"Quelle est la prochaine action concrète que ce système devrait permettre de mieux faire ?"*
> Si floue → retour à l'objectif initial.

---

## VII. Protocoles d'interruption

> [!tip] In-game · Timebank
> Protocole Avant session maintenu même sous engagement intense.
> Règle : pas d'augmentation du volume pendant une session perdante sans validation explicite du budget L0.

> [!tip] Avant session
> Question de recalibrage hebdomadaire : *"Est-ce que cette complexité sert encore l'objectif initial ?"*

> [!tip] Post-session · Review
> Si session longue et perdante : nommer la Suramplification. Identifier le moment où l'engagement est devenu disproportionné.

> [!tip] Si L0 épuisé
> Le signal d'arrêt naturel est moins perçu. Poser la question de recalibrage explicitement avant de continuer.

> let p = dv.current();
> 
> // Extrait le pôle défensif depuis le nom de fichier : "04 — Foo -- Bar" → "Bar"
> // Ou utilise le frontmatter "pôle_défensif" si présent
> let targetPattern;
> if (p["pôle_défensif"]) {
>     targetPattern = p["pôle_défensif"];
> } else {
>     let nameParts = p.file.name.split(" -- ");
>     targetPattern = nameParts.length > 1 ? nameParts[nameParts.length - 1] : p.file.name;
> }
> 
> let orPage = dv.page("📝 observation et ressentis");
> if (!orPage) { dv.paragraph("*⚠️ Fichier O&R introuvable.*"); return; }
> 
> let content = await dv.io.load(orPage.file.path);
> 
> let sections = content.split(/\n##\s+/);
> let matches = [];
> 
> let dateRe = /^(\d{2}-\d{2}-\d{4})/;
> let escaped = targetPattern.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
> let tagRe = new RegExp("\\[pattern::[^\\]]*" + escaped + "[^\\]]*\\]", "i");
> 
> for (let section of sections) {
>     let firstLine = section.split('\n')[0].trim();
>     let dateMatch = firstLine.match(dateRe);
>     if (dateMatch && tagRe.test(section)) {
>         matches.push(dateMatch[1]);
>     }
> }
> 
> if (matches.length === 0) {
>     dv.paragraph("*Aucun O&R lié — tagger avec `[pattern:: " + targetPattern + "]` dans l'O&R.*");
>     return;
> }
> 
> matches.sort().reverse();
> let rows = matches.map(date => {
>     let allMR = dv.pages('"Journal/Morning routine logs/2026"').where(p => p.file.name === date + " Morning routine"); let mrPage = allMR.length > 0 ? allMR[0] : null;
>     return [date, mrPage ? mrPage.file.link : "*" + date + " (MR introuvable)*"];
> });
> dv.table(["Jour", "Morning Routine"], rows);
> ```
